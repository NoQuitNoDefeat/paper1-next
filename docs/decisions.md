# 实现决定与依据

记录本版本做出的选择、依据，以及与旧工程和研究方案第 19 版的差异。参数可在配置中修改。每条标明是普通工程选择，还是**环境或方法语义的改变**。

## 1. 环境语义（Python 轻量后端）

| 项目 | 本版本 | 依据 / 差异 |
| --- | --- | --- |
| 登记下一跳队列 | 全部有向节点对 N(N−1)，由场景在回合开始前显式声明，回合内固定 | 第 19 版要求集合固定、不用未来路由倒推，并写明不“默认”登记全部节点对。移动网络中任何节点都可能成为下一跳，所以这里是显式声明，不是暗中默认。分母固定使奖励尺度稳定。旧实验同样如此。 |
| 路由变化后的旧队列 | **默认 `rehome`**：下一跳改变的已排队包按（入节点时间，ID）顺序重新接纳；保留 `keep` 作对照 | **环境行为改变。** 第 19 版中已排队包原地不动。旧实验里滞留包最长等了 26 s，造成大量丢包。重新安置不改变奖励定义。 |
| 等待区恢复时目标队列已满 | 包留在等待区（继续受等待超时约束） | 旧实现直接丢弃。改为不产生可避免的容量丢包。 |
| 入队时间 / HOL | 入队时间 = 包进入当前队列的边界时刻；HOL = 采样时刻 − 当前队首的入队时间 | 与旧版一致。重新安置的包取进入新队列的时刻。 |
| 时序 | 周期 20 ms，服务窗口覆盖整个周期；采样、计划和执行在同一边界（同步环境） | 见 ns-3 对接说明：同步环境可以令这些时刻相等。 |
| 终止 | 等待超时（1 s）、队列容量拒绝、等待区容量拒绝；端到端期限和重传上限可用，默认关闭 | 旧版强制关闭期限和重传。 |
| 执行信道 | 主：`ideal`（决策估计 = 执行真值）；变体：`lognormal`（估计误差 + 执行衰落 + 窗口内移动） | 失败传输保留包及其 FIFO 位置，不计为终止。 |
| 回合结束 | 到达时限 → `truncated`（用最后有效状态的价值自举）；`terminated` 只在设置 `terminate_when_drained=true`、业务停止且网络清空后出现 | 执行错误抛 `ExecutionError`，单独报告。 |

## 2. 场景默认值与校准

物理参数沿用旧实验：P = 0.1 W，N0 = 1e-11 W，路径损耗 1 m 处 40.05 dB，指数 2.5，SINR 门限 3（4.77 dB）。无干扰单跳距离约 161 m。

改动如下，均为普通参数选择（configs/base.toml）：

- **速率 4 Mbps × 20 ms → 每条链路每周期 9 个 1024 B 包。**
  - 旧设置下（每 50 ms 48 个包，而队列只有 32 包），调度一次就能清空队列，调度选择意义不大。
- **16 个节点，区域 300 m × 300 m**，高度 80–120 m。每回合抽取速度 5–30 m/s、每流负载 10–30 包/秒，每个节点发起一条流。
  - 回合 500 个周期（10 s），路由每 25 个周期（0.5 s）更新一次。
- **路由：在 SNR 余量 ≥ 6 dB 的链路上取最少跳，不可达时回退到全部链路。**
  - 纯最少跳会选靠近门限的长链路，这类链路几乎没有干扰余量，计划平均只有约 1.3 条链路。
  - 这是环境的路由参数，不是 MAC 决策。

校准结果（4 回合 × 300 周期，每流 20 包/秒；交付率 / 平均时延）：

| 区域 / 节点数 / 路由余量 | random | longest_queue |
| --- | --- | --- |
| 400 m / 12 / 0 dB | 0.73 / 0.45 s（断连导致 14–17% 丢包） | 0.81 / 0.19 s |
| 300 m / 16 / 0 dB | 0.82 / 0.70 s | 0.96 / 0.25 s |
| **300 m / 16 / 6 dB** | **0.70 / 0.98 s，计划 1.99** | **0.87 / 0.53 s，计划 1.94** |

- **提升空间：** 穷举显示，贪心计划常比最大可行集合少 1 条链路（2 vs 3，偶尔 2 vs 4），学习选择顺序有改进余地。
- **约束对照**（longest_queue，同一批场景）：

  | 约束 | 交付率 | 执行失败 | 含 SINR 违反的周期 |
  | --- | --- | --- | --- |
  | 完整 SINR | 0.85 | 0 | 0 |
  | 两两相容 | 0.81 | 22% 链路 | 27% |
  | 只查新增链路 | 0.43 | 55% | — |
  | 仅资源约束 | 0.05 | 97% | — |

## 3. 观测与双图

- **通信图：** 全部物理可用的有向链路（无干扰 SNR ≥ 门限）。
  - 节点特征（15 维）：出队列占用与最大 HOL、等待区占用与紧迫度、位置、速度、度、邻居集合 Jaccard 稳定性、候选出链路数、可达目的地比例。
  - 边特征（11 维）：队列占用、HOL（上限 2 × 0.2 s）、路由标记、SNR 余量、距离、距离变化率、链路年龄、存活 EMA、质量趋势、候选标记、反向队列占用。
- **候选：** 登记队列非空 ∧ 是当前下一跳 ∧ 无干扰 SNR ≥ 门限。局部编号按登记队列 (tx, rx) 字典序；`cand_link` 保存稳定物理链路 ID。
- **链路交互图：**
  - 共享端点的候选之间总有边（同发 / 同收 / 发 = 收 / 收 = 发）。
  - 有向干扰边的强度是源发射机占用目标链路干扰预算的比例，即 `P·G(s_a, r_b) / (S_b/θ − N0)`。比例 ≥ 0.02 才保留，每个目标最多保留最强的 8 条。
  - 这些边只用于表示；可行性始终按完整累计 SINR 检查。
- **历史特征：** 年龄、存活（β = 0.9）、SNR EMA 趋势（α = 0.8）、距离变化率、邻居稳定性，每个边界只用当前和过去的报告更新一次。`tests/test_observation.py` 检查未来位置不影响当前观测。

## 4. 模型

`dual_graph`，设置如下：

- 隐层 64；
- 2 层有向、边条件的通信图编码器（入向和出向消息分开，均值聚合）；
- Lift = LN(MLP[h_tx, h_rx, x_link] + W·x_link)，保留直接链路特征通路；
- 1 层链路交互图编码器；
- 门控求和摘要，从 0 开始；
- Actor 为 MLP[z_i, s, ctx]，最后一层初始化乘以 0.01，初始策略接近均匀；
- Critic 为 MLP[ctx, s, 剩余可行候选的均值, 全部候选的均值, 4 个控制器微特征]；`ctx` 含等待区摘要，所以空候选或只有等待积压时边界价值仍然有意义；
- Actor 与 Critic 共享主干（`share_trunk=false` 可分开）；
- 不用 dropout 和批归一化，训练与评估模式下概率完全一致。

隐层 64 时约 26.7 万参数。

每个子部件都有消融对照：`comm_encoder=node_mlp`、`lift=context_only`、`interaction_encoder=none`、`set_summary=none`。

- **采样切片：** 回合跨迭代继续。每个切片末尾记为 `cut`，用当前状态的价值自举并阻断递推。
- **奖励标准化：** 奖励除以折扣回报的滑动标准差。这只影响学习信号；日志和评估一律使用原始奖励。
  - 理由：对 240 个队列取平均后，原始奖励量级只有约 0.01–0.03；旧实验中 Critic 的解释方差为负。
- **续训：** 见 architecture.md 第 4 节。
- **模仿预热（可选，`[imitation]` 配置段）：** 先让模型拟合某个教师策略（默认 longest_queue）的逐步动作，Critic 同时回归教师策略的折扣回报，然后再用 PPO 训练。
  - 这只改变训练起点，调度方法不变。
  - 教师记录复用 PPO 的重算路径，所以掩码、摘要和动作的定义与采样完全一致。
  - 预热后，奖励标准化器从教师回报的尺度开始，保证 Critic 的量纲前后一致。

## 5b. 方法变更：主方法不再使用已选摘要（用户 2026-09-24 确认）

**变更**：定稿主方法 `configs/protocol_final.toml` 的设置为 `set_summary = none`。原门控求和摘要（研究方案原设计）保留为可切换的对照（`protocol_a20.toml`）。代码没有删除任何实现，只调整了角色标签：

| 实现 | 角色 |
| --- | --- |
| `none` | 主方法 |
| `gated_sum` | 对照 |
| `gated_mean` | 变体 |
| 控制器动态特征（`candidate_dynamics`） | 变体 |

**依据**（dev 集，预先登记的规则）：

- E6/E6b：在默认场景和 4 个困难场景中，去掉门控求和摘要后交付率不变，平均时延低 4–5%，p95 低 3–4%。
- E8：两种改进方案（归一化摘要、控制器动态特征）都以每个场景 0.2–0.6 个百分点的交付率换取更低时延，未通过“交付率优先”的判定规则。

**不变的部分**：

- 每周期对双图只编码一次；
- 逐条选择，由完整累计 SINR 控制器维护资源、干扰和掩码；
- 没有 STOP，输出极大可行集合；
- 微步 PPO 的时间与折扣含义；
- 模仿预热。

**含义的变化**：没有摘要时，Actor 在一个周期内对各候选的评分固定。策略相当于“每周期学习一个优先级顺序，再由控制器按掩码逐条选出可行集合”，“按已选集合调整后续选择”的能力由控制器的掩码和微特征体现，而不是由学习到的摘要体现。研究表述要相应调整。

**历史配置不变**：`protocol_a20.toml` 与 E6/E8 的消融配置保留原样，以便复现历史实验。之后在定稿协议下做新消融时，配置应继承 `protocol_final.toml`。

## 8. ns-3 执行语义（2026-09-25）

用户确认：ns-3 验证以论文主线为中心，旧工程只作有限参考。下列内容都不是交付要求：

- ACK 协议；
- 独立控制信道；
- 同信道 ACK 压力测试；
- 与旧工程的兼容。

因此执行规则按本项目的方法和 Python 环境来定，目的是检验规划模型所依赖的假设。

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 执行方式 | `execution="phy"`（默认）：DATA 帧经 ns-3 Spectrum 信道和 HalfDuplexIdealPhy 发送，用 Shannon 误码模型在实际累计干扰下判决 | 独立实现的包级物理层，干扰随链路开始和结束而变化，不是按公式重算 |
| 送达确认 | 正确接收由集中式控制面确认，不占数据信道空口（C++ 中的 `ideal-spectrum-v1`） | 与方法和训练环境的集中调度假设一致 |
| 失败处理 | 队首失败则该链路本周期停发，队首和后续包原位保留，下周期重试 | 与轻量环境一致；FIFO 和 HOL 不变 |
| 帧内运动 | `motion=true`（默认）：节点在周期内按场景的运动模型连续运动（盒内镜面反射），每次接收开始时按当前距离重算增益 | 规划只用周期起点的信道，这正是要检验的近似；C++ 中去掉了“运动必须配 ACK”的限制 |
| 帧开销、传播 | 24 B 身份头，1 μs 传播 | 真实执行代价；默认参数下每周期仍可发 9 个包 |
| 解码门限 | 带宽取值使门限 SINR 下恰好可传“帧长 + 1”字节，并留 1e-6 相对余量 | ns-3 的 Shannon 模型先向下取整，再要求可传字节数严格大于帧长。所有帧同长且同时开始，每帧只有一个干扰区间，因此物理层解码条件与规划的 SINR 条件等价（有测试） |
| 账本对齐 | `execution="ledger"`：ns-3 账本在观测增益上执行完整 SINR 规则 | 只用于逐包核对 ns-3 账本与轻量环境一致（迁移正确性） |
| 队列语义 | 仍支持 `stale_queue_policy` 的 rehome（主）和 keep（对照）；等待区恢复遇队列满时一律留在等待区 | 与轻量环境相同 |
| 已删除 | 轻量环境的 `waiting_restore="drop"` 旧账本模式；INIT 中的 `waiting_restore` 字段；Python 侧的 `transaction-ack-v1`、`controlled-budget-v1` 入口；`full_sinr_bidirectional` 约束变体 | 只为兼容旧规则或 ACK 研究而存在，不属于论文主线 |
| 不建模 | 空口 ACK、控制信道和报告丢失、小尺度衰落、多速率 | 见 known-issues.md |

C++ 模块中继承来的 ACK 事务、控制信道和 Wi-Fi 探针代码保留在源码里，但本项目不使用，也不维护。

**配置注意**：`--set backend.type=ns3` 会按配置规则清空整个后端配置段，路由会退回默认参数（没有 6 dB 余量）。切换执行后端要用 `fanet-next eval --backend ns3`，它会保留路由、信道和队列参数。
