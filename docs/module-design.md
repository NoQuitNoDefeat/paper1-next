# 模块化与自主决策

模块化用于方便科研替换与比较。以下是八类职责建议，最终如何分文件、分层、合并或拆分，由 CC 判断。

## 1. 模块与选择

| 模块 | 做什么 | 可选择的实现 |
| --- | --- | --- |
| 场景与业务 | 产生初始状态、移动、路由和业务过程 | 固定输入或生成器；规模、负载与动态性配置 |
| 环境与执行后端 | 执行计划、推进时间和包状态、返回事实 | Python 轻量环境、后续 ns-3；状态和执行组织 |
| 观测与双图 | 从可用报告构造图、特征和候选映射 | 因果特征、历史长度、归一化、图构造与稀疏方式 |
| 模型 | 提取图表示、候选评分、价值估计、已选摘要 | 图网络类型、宽度/深度、融合与池化、Actor/Critic 共享方式 |
| 微步调度与约束 | 逐条选链路，维护可行集合并生成计划 | 增量干扰、掩码维护、缓存、摘要组织；主方案与明确标记的约束对照 |
| 奖励与指标 | 从实际事件和快照计算反馈与统计 | 奖励权重、参考尺度、计算与记录方式 |
| 训练 | 采样、优势计算、PPO 更新、恢复训练 | 优化器、学习率、批量、训练长度、采样并行和诊断 |
| 实验与评估 | 装配方法、运行比较并记录结果 | 配置组织、入口、种子、日志、图表、开发对照与消融 |

研究语义见 [研究方法](research-method.md)。上表是选择空间，不是首版待实现清单。

## 2. 优先保持清楚的边界

**模型与微步控制。** 采样、PPO 重算和评估共用模型与动作定义。模型提供编码、摘要更新、评分和按需估值等能力；控制器维护完整资源与可行性。控制器不依赖编码器内部层名或固定维度。具体 API 自主，不要求继承旧包装方法。

**决策与执行。** 决策器输出完整周期计划，后端执行并返回实际服务、事件和下一观测。一次运行由所选后端推进权威包状态，避免 Python 和 ns-3 重复执行服务。两者的无线效果可以不同，但身份、动作和时间含义清楚。

**事实与奖励。** 环境提供真实执行事实和需要的采样快照，奖励解释这些事实。保留奖励分项，便于判断策略学到了什么。

**方法装配。** 普通构造函数、小字典或简单工厂均可。按真实比较需求实现第二种组件，再提炼公共接口；不预建动态发现、安装或热加载管理。组合选择能够检查必要的特征、动作和模型兼容关系即可。

## 3. 自主决策范围

- **直接决定：** 目录、命名、依赖、数据结构、接口形式、缓存、配置、日志、测试工具、复用/重构/重写和实现顺序。
- **自主试验并简要记录：** 网络类型与尺寸、参数共享、因果特征组合、归一化、奖励权重、训练参数、采样方式和开发消融。无需逐项询问。
- **需要先讨论的实质变化：** 重新选择研究问题或核心主方法，例如放弃双图/微动作 PPO，转向路由或轨迹联合优化，改变动作与停止机制、可获得信息条件或主要优化目标。先说明变化及理由即可，不设置额外审批流程。

明确标记的消融或基线不等于替换主方法，可自主实施。新方法表现需要验证，工程重写本身不作为效果提升证据。

## 4. 可运行目标

先具备一套双图微动作 PPO、Python 环境和必要的简单基线，能够训练、评估、保存及本版本续训。实现哪些后续变体由实际研究需要决定。

恢复状态按真实需要覆盖模型、优化器、进度、配置和相关随机状态。记录支持的恢复边界；环境状态不支持恢复时说明保证范围。旧检查点兼容不是要求，新版本也不承诺任意模型或配置变化后都能无缝续训。

用少量有针对性的行为检查验证关键语义，再结合训练诊断和基线比较推进。实验保留足以定位方法组合、配置、种子与代码来源的信息，记录形式自主。
