# 研究方法

本文提炼现有方案中的科学问题和方法，作为新实现的起点。具体参数和代码组织不固定；可自主选择并验证实现方案。本文描述的是方法含义，不是旧代码的兼容规范。

## 1. 研究什么

面向高动态 UAV/FANET，集中式调度器根据当前可获得的网络与业务状态，在每个物理周期选择可并发发送的一跳链路集合，改善长期有效服务、队列、时延和可靠性。

移动、业务产生和路由更新由环境提供，MAC 负责选择服务哪些下一跳队列。起点采用单射频、半双工、单信道和给定发射功率。无有效路由的包进入独立的有限容量、有限等待时间等待区，等待区不是可直接调度的链路。

## 2. 双图怎样表示网络

- **通信图：** 无人机是节点，当前有向通信链路是边，表达节点状态、队列、基础链路条件和因果动态信息。
- **候选链路：** 物理可用、路由允许、对应下一跳队列非空，并满足独立于最终并发集合的基础质量条件。
- **链路表示（Lift）：** 结合通信图编码得到的发送端、接收端上下文与直接链路特征，保留链路方向和逐链路差异。
- **链路交互图：** 候选链路成为节点，边表达资源竞争与有向干扰；进一步编码后供策略评分和价值估计使用。

网络层类型、层数、宽度、聚合、融合和 Actor/Critic 参数共享可自主比较。直接链路信息通路是表示设计的一部分，不声称数学上无损。

输入限于决策时可获得的信息。历史统计可表达链路年龄、近期稳定性和质量变化；具体组合与尺度可以调整并记录。仿真器持有未来轨迹不代表模型可以使用它，当前动作结果进入奖励和下一次观测。

局部候选编号、图张量行与稳定物理链路身份之间要能对应，尤其在跨周期、批处理和 PPO 重算时。

## 3. 微步怎样形成调度

每个物理周期在决策快照上编码双图一次，随后逐条选择可行链路。微步更新已选集合、剩余资源、累计干扰、可行掩码和已选摘要。

Actor 对当前可行候选评分；训练按掩码概率采样，评估注明采用采样或贪心。Critic 估计微状态的未来收益，输入需反映已选集合、剩余选择及业务/资源状态；空候选和仅有等待积压仍需要适当的边界价值。

已选摘要可用从零开始的门控求和作为初始实现：

`summary_next = summary + sigmoid(W @ embedding + b) * embedding`

摘要实现及维度由 CC 选择。PPO 更新时，用当前参数和保存的动作前缀重算摘要，梯度能够回到相关模型组件。

起点无学习式 STOP：可行候选耗尽时自动结束。输出是不能再加入链路的极大可行集合，策略主要通过选择顺序影响最终集合；极大不等于最优。空候选周期没有 Actor 动作，但仍执行一次周期边界转移。

无 STOP 的即时服务单调性依赖固定服务窗口、没有额外激活成本等条件；不能将其外推为长期最优，或作为计划大小影响控制时延时的最优性证明。

## 4. 可行性怎样判断

主方案使用资源条件和完整累计 SINR。对链路 l=(s_l,r_l)：

`SINR_l(S) = P_s_l * Ghat(s_l,r_l) / [N0 + sum_{m in S, m!=l} P_s_m * Ghat(s_m,r_l)]`

加入新链路后，集合内所有链路均需满足各自门限，包括原已选链路。单射频半双工起点下，一个节点不能同时参加多条传输；同信道不自动代表硬冲突。

计算可以增量更新或缓存。交互图的稀疏边用于模型表示，不能替代完整集合干扰；只查新增链路或只查两两相容是不同的约束方案，可明确作为对照。

可行性基于决策时的信道估计。实际无线执行可能因移动、误差或时延失败，奖励取执行事实。

## 5. 微步 PPO 的时间含义

| 转移 | 奖励 | 折扣 | 学习用途 |
| --- | --- | --- | --- |
| 选择一条链路，进入下一微状态 | 0 | 1 | Actor、Critic、优势计算 |
| 执行完整计划，进入下一物理周期 | 本周期奖励 | γ | Critic、优势计算；没有 Actor 动作 |

微步构造不逐次推进物理环境。不同选择数量不应变成不同次数的物理时间折扣。空候选周期仍有无动作的边界记录，采样切片在完整物理周期边界进行。

原方法使用时变折扣计算 TD/GAE：

`delta_n = r_n + Gamma_n * B_n * V_old(next) - V_old(current)`

`A_n = delta_n + Gamma_n * lambda_GAE * C_n * A_next`

B 表示是否使用下一状态价值，C 表示是否沿采样记录继续递推；λ_GAE 在该起点定义中按每条微转移作用。它与物理时间折扣分开。

正常转移使用对应下一微状态；外部截断/采样切片保留同一回合最后有效状态的价值，但阻断跨切片递推；明确任务终止才取消后续价值。执行错误单独报告，不伪装为正常结束或零奖励。

采样保存当时的图输入、候选映射、掩码、动作、旧概率和价值及结束类型。更新用当前参数重算同一输入和动作前缀，避免只缓存旧嵌入而无法训练编码器。Actor 损失只用有动作记录，Critic 和优势计算覆盖两类记录。随机层或模式切换要与概率重算的定义一致。

## 6. 奖励与评价含义

周期奖励起点为：

`r = alpha * 服务 - beta * 剩余队列 - eta * 时延压力 - lambda_viol * 终止违约`

权重和参考尺度可自主试验。原方法各分量含义如下：

| 分量 | 统计含义 |
| --- | --- |
| 服务 | 实际成功从权威下一跳队列移除的完整包字节数，按链路参考服务量归一化后对登记队列平均 |
| 剩余队列 | 服务后、终止丢弃及新接纳前的队列占用/容量，对全部登记下一跳队列平均 |
| 时延压力 | 对同一总体平均 `占用/容量 × min(服务后队首等待时间/参考时间, 1)`，空队列贡献零 |
| 终止违约 | 按稳定 ID 去重的互斥终止包数/风险包数；风险总体是期初队列与等待包，加本周期新源端包 |

队列总体包括空队列、未被选中和暂不可调度的队列；等待区单独记账。无登记队列时前三项为零，等待终止仍可能有惩罚。权重 λ_viol 与 GAE 参数是不同量。

基本顺序是：执行实际服务 → 周期末采样服务后的队列/HOL → 处理到期等终止 → 路由恢复与接纳 → 汇总事件并结算周期奖励。周期内新出生与中继到达先暂存；同刻到期先于恢复。FIFO、容量拒绝及包时间戳应有一致定义，新队首的等待时间由其自身入队时间计算。

服务容量、计划发送、丢弃和等待转入均不等于成功服务。一次失败传输不自动算作包终止；期限、等待超时、重传上限和容量拒绝按实际启用机制处理并避免重复计数。

上述是初始奖励定义；权重和尺度可调。若改变统计总体、结算时序或目标，明确说明方法变化，避免将含义变化当成普通数值调参。

评价另记录最终交付率/有效吞吐、端到端时延、队列与等待积压、终止原因、约束违反和计算成本。一跳服务可能重复计入中继跳，HOL 是时延代理，两者分别不能直接当最终交付吞吐和端到端时延。

## 7. 怎样判断实现和学习是否有效

用少量可手算场景检查集合干扰、空候选、多个微步、包守恒、队首变化、丢弃前采样、终止/截断、PPO 概率与梯度。再用随机合法、队列优先等简单基线和训练诊断检查学习效果，按需要扩展消融。

正式比较保持输入条件和指标含义明确，开发调参与最终测试分开，记录方法、配置、种子与模型来源。测试通过证明所检查的行为，训练曲线和比较结果才用于判断方法效果。
