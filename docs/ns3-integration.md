# ns-3 对接

当前主训练先用 Python 轻量环境；ns-3 用于后续无线验证。这次仅准备说明与已有代码入口，不复制 ns-3 本体或构建环境，也尚未完成新项目的无线对接。

## 1. 后端放在哪里

`当前报告 → 观测/双图 → 模型与微步调度 → 完整计划 → 后端执行 → 事件和下一观测 → 奖励/指标`

图、模型、微步调度及公共奖励定义留在 Python 侧。ns-3 推进该次运行的状态与无线事件，返回执行事实；无需理解模型隐藏维度，也无需每选一条链路就往返通信。

接口形式和通信机制由 CC 在实际接入时选择。先保证计划、观测、事件和时间含义明确。

## 2. 对接的逻辑内容

| 内容 | 需要表达什么 |
| --- | --- |
| 初始化 | 场景、初始包/队列/路由、时间范围、后端能力和运行身份；未来外生过程仅由后端持有 |
| 观测 | 运行与周期、采样时刻、实际可用报告、队列/等待/路由及当前物理估计 |
| 计划 | 对应观测、稳定有向链路 ID、完整发送计划、生成/执行/截止时间 |
| 结果 | 原计划与实际执行集合、成功服务包和字节、失败/终止原因、服务后快照和下一有效观测 |
| 结束 | 任务终止或外部截断及最后有效状态；通信/执行错误单独表示 |

这是逻辑内容，不固定字段名或序列化格式。统一声明单位、链路方向、包 ID 和 FIFO 顺序；未知或不支持的值与有效零分开。

采样、报告汇聚、计划生成、命令到达、执行与截止具有不同含义。同步环境可令部分时刻相等；非冻结无线运行按其模型推进。计算墙钟、进程通信等待和仿真时间分别记录，只有明确的时延规则才将测量值计入仿真。

一次运行由所选后端推进权威包状态。计划可行不等于实际成功，奖励使用实际成功出队量。执行后的信道与结果不能回填当前策略输入。

既有 v2 无线路径描述 DATA/ACK 集中式事务确认：DATA 接收先形成非权威副本，发送端收到 ACK 才提交一次服务；失败保留原包和 FIFO/HOL 供后续周期重试。它不是完整分布式 MAC 或 IEEE 802.11 的复现。

既有移动路径在每次接收开始采样传播条件，单帧接收功率采用准静态近似；其他信号仍能改变干扰，不能说整帧 SINR 恒定。控制路径限定完整、新鲜报告，尚不能据此声称支持缺失报告下继续运行。复用时检查这些能力是否符合新实验需求。

## 4. 后续怎样接入

新项目开始无线对接时，再检查旧适配与旧数据结构的耦合，选择复用所需自有代码、转换层或重做部分适配。选定明确来源版本，在新工程或独立构建位置工作，保留必要测试和依赖来源；不修改正在并行工作的原工程。

新项目不必沿用旧协议布局。若复用旧协议则遵守对应版本，若重新设计则明确双方含义和版本。

先用小场景核对包守恒、完整计划、服务、边界和关闭，再覆盖空计划、多链路、失败与窗口不足。实际 ACK 路径单独检查 DATA 成功但 ACK 失败不会被算作服务或重复交付。受控假设相同可做确定性对齐，实际无线模型允许物理结果不同。通信跑通、语义对齐与无线有效性分别说明证据。
