本文写给第一次阅读本工程的人和 AI 助手（协作者）。内容依次为：

- 工程是什么；

- 按问题划分的阅读路线。

## 1. 一段话说明

工程研究 UAV 自组网（FANET）的集中式 MAC 调度。每个 20 ms 周期里，调度器从候选的一跳链路中选出一组同时发送的链路，目标是交付更多包、时延更低。

主方法是双图表示加微步 PPO。

- **双图**：通信图描述无人机和链路，链路交互图描述候选链路之间的冲突与干扰。
- **微步**：每个周期对双图编码一次，然后逐条选择链路。控制器检查半双工和完整累计 SINR，可行链路选完就结束。
- **训练**：先模仿 longest_queue（LQ）预热，再用 PPO 微调。

实验在 Python 轻量环境中训练和评估，并用 ns-3 物理层执行复核。评价以交付率为先，时延次之。

**当前状态**（2026-10-03）：E1–E17 已完成。

- 方法已定稿，配置为 `configs/protocol_final.toml`；之后的实验都没有改动它。
- 主要结论来自：
  - E9：测试集；
  - E10：ns-3；
  - E11：12 个外部基线；
  - E12b：按实测文献标定的信道；
  - E13、E13b：真实群集轨迹、第三方移动模型和实测收包。
- 探索实验 E14、E15、E15b、E17 另设配置和结果目录，不改变上述结论；确认实验 E16 用的是一份独立的真实群集数据。
- 公开数据的筛选与使用见 `docs/data-screening.md`。

## 2. 主要结论速览

下表中的差值都是主方法减对照。交付率差单位为百分点，括号内为按场景配对的 95% 置信区间。

“可靠性可接受”指交付率差的置信区间下界 ≥ −0.5 个百分点，即不劣于对照的标准。详细数字和判定在 `docs/experiments.md` 对应实验的“结果”小节。

| 结论 | 证据 | 关键数字 | 性质 |
| --- | --- | --- | --- |
| 交付率不低于 LQ，时延显著更低；条件越难优势越大 | E9（5 个场景族，各 64 个测试场景） | 5 个族都可接受；平均时延低 7–15%；4 个困难族交付率高 0.9–2.3 | 主要结论 |
| 训练环境的判定在包级物理层下成立 | E10（ns-3） | 优势在 ns-3 中复现；完整 SINR 策略在两种执行下交付率差 ≤ 0.12 | 主要结论 |
| 优于 12 个外部基线，包括前人的学习方法 | E11 | 5 个族交付率都最高；60 个比较中 58 个显著更高；相对只差动作形式的“独立决定 PPO”高 3.7–9.1 | 主要结论 |
| 与反压是一组取舍 | E11 | 反压时延低 0.12–0.58 s，但交付率低 1.4–5.3，且用了主方法没有的目的地信息 | 主要结论 |
| 按实测文献标定的信道下仍然成立 | E12b | 默认场景 +0.85 [+0.29, +1.40]，时延 −0.32 s；24 节点 +2.58；低负载 −0.34，可接受。单速率加衰落裕量使所有方法下降 18–24 | 主要结论 |
| 真实群集轨迹上零样本与 LQ 持平、时延更低；在数据上重新训练后交付率最高 | E13、E13b（Vásárhelyi 30 架，3 折） | 零样本 +0.03 [−0.46, +0.51]，时延 −0.26 s。重新训练后 +0.39 [+0.11, +0.68]，在 19 个策略中最高，显著高于每个重新训练的学习基线（+0.38 到 +3.22） | 主要结论 |
| 零样本的弱点：低速、紧凑机群 | E11、E13、E13b | 速度 0–5 m/s 时 −0.34；4 m/s 飞行 −0.52；30 架 −0.78；相对“仅模仿”−0.12 [−0.63, +0.40]。这几处未达标准 | 主要结论（局限） |
| 链路抽象与实测收包相符，但实测起伏更大 | E13 结果四（UCSB 空地实测） | 分段收包率误差：莱斯模型 0.06，无衰落门限 0.26。RSSI 分解为慢变约 4.2 dB、快变约 3.0–3.3 dB | 主要结论（B 类） |
| 训练分布覆盖低速紧凑后，30 架的弱点消失 | E14 | 群集 30 架：−0.90 → +0.03；合成低速紧凑：−0.96 → −0.46，仍未达标；默认场景不退步，时延略升 | 探索 |
| 阴影的建模口径会改变结论 | E15、E15b | dB 零均值阴影抬高平均功率、改善连通性：各方法 +7 到 +31，主方法优势消失。功率归一后，四处判定全部成立，24 节点 +1.52 [+1.04, +2.00] | 探索 |
| 评论者看不到正在形成的计划内容：属实，但补上后没有改善 | 诊断 D1、D2，E17（开发集） | 计划选完时评论者只知道条数；让评论者看见计划后，排序与实际回报接近随机，交付率和时延不变；去掉周期内估值变化反而使交付率下降 | 探索 |
| 独立真实群集上的确认 | E16（Verdoucq 10 架，零样本） | 主方法 −0.22 [−0.34, −0.10]、宽分布主方法 −0.05，都可接受；宽分布相对原版 +0.17 [+0.11, +0.23]，四次飞行方向一致 | 确认 |

**不能说或要加限定的**：

- **“零样本在真实群集上领先 LQ”不成立。** 只能说持平，而且结果随场景抽样而变：E15 那批种子上，无阴影时为 −0.41 [−0.78, −0.04]。
- **“时延显著更低”只对 LQ 类启发式和学习基线成立。** 反压基线的时延更低。
- **低速情形的改善只有 E14 一处探索性证据。** E16 的数据拓扑变化快，不能确认这一点。
- **训练分布的改动（E14）还没有并入定稿方法。** 是否采用需要作者决定。

## 3. 阅读前要知道的几点

1. **有些文字是写给开发 AI 的任务说明，阅读和审阅时不适用。** 这包括：
   - `CLAUDE.md`；
   - README 中“给 Claude Code 的任务”一节；
   - `docs/module-design.md` 中的自主决策范围。

   它们是作者交给开发会话（Claude Code）的工作指令，不是对读者的要求。
2. **指向 `/Volumes/FANET_Data/...` 的链接是作者本机的旧工程**，开发时只读参考。阅读本工程不需要它们，缺失也不影响理解。
3. **定稿主方法与 `research-method.md` 有一处不同：不使用学习的已选摘要。** `research-method.md` 描述的是项目起点；这项变更及其依据见 `decisions.md` 第 5b 节。
4. **`experiments.md` 按时间顺序记录，开头有索引。**
   - E1–E8 是开发过程，其中有中途放弃的设置，例如从零训练的 PPO 和门控求和摘要。
   - 主要结论看 E9–E13b，探索看 E14、E15、E15b、E17（及诊断 D1、D2），确认看 E16。
   - E12 因路由问题由 E12b 取代，原因写在“E12 更正”中。
5. **`results/` 不在版本库中。** 运行目录、检查点和原始汇总都只在作者本机，所需数字已写入 `experiments.md`，因此复现评估需要重新训练。
   - 结果报告页由 `tools/build_report.py` 从结果文件生成，含全部图表；需要时可以向作者要链接。
   - 真实数据要按 `data/sources.json` 下载，再用 `tools/data/` 下的脚本转换。原始数据和处理后的轨迹都不进版本库。
6. **每个实验的判定规则都在测试集开跑前写入 `experiments.md`（“预先登记”）。**
   - 测试种子的使用记录见 `known-issues.md` 第 18 条。
   - E13b 和 E15b 有意沿用前一个实验的测试场景，以便逐场景配对，原因写在各自的预登记中。
7. **`configs/explore/` 下是探索用的配置，不是定稿方法。** 例如 E14 的宽训练分布。

**主方法的代码路径**（均在 `src/fanet_next/` 下）：

1. `contracts.py`：模块之间传递的数据（Report、SchedulingProblem、DualGraph、Plan、CycleFacts）。
2. `loop.py`：`SchedulingEnv`，唯一把各组件连起来的地方。一个周期的流程是：报告 → 候选 → 双图 → 策略 → 计划 → 执行 → 奖励。
3. `backend/lightweight.py`、`physics.py`：轻量环境的包级执行和 SINR 计算。
4. `scheduling/`：
   - `candidates.py`：候选链路；
   - `constraints.py`：半双工与完整累计 SINR；
   - `controller.py`：微步控制器，维护已选集合和可行掩码，不依赖模型。
5. `observation/builder.py`、`observation/graph.py`：由报告构建双图及其特征。
6. `model/`：
   - `dual_graph.py`、`components.py`：编码器、Lift、交互图编码、Actor/Critic；
   - `runner.py`：逐条选择，采样与 PPO 重算共用这一份代码。
7. `policy/learned.py`：PPO 策略。
8. `training/`：
   - `imitation.py`：模仿预热；
   - `collector.py`：采样；
   - `advantages.py`：微步时变折扣 GAE；
   - `ppo.py`：更新。
9. `reward/standard.py`：奖励分项。`reward/metrics.py`：评价指标，与奖励分开记录。
10. `experiment/`：配置装配（`assemble.py`）、命令行（`cli.py`）、训练、评估和检查点选择（`select.py`）。

配置 `configs/protocol_final.toml` 依次继承 `protocol_a20.toml`、`imitation_lq.toml`、`base.toml`，最终参数以 `base.toml` 为底。

**场景与信道**（`scenario/`）：

- `random_scenario.py`：合成场景，用于训练。
- `trace.py`：回放记录的轨迹，按整条轨迹划分训练、开发和测试。
- `mixture.py`：多个场景分布按种子混合，只用于 E14 探索。
- `channel.py`：信道。`rician` 是按实测参数设定的空空信道，含衰落裕量和可选阴影。

**基线**（定义见 `decisions.md` 第 9 节）：

- 启发式：`policy/heuristics.py`。
- 精确最大权（MILP）、反压、局部搜索、空间 TDMA：`policy/classical.py`、`scheduling/maxweight.py`。
- 前人的学习方法（Zhao-GCN、GRLinQ 式、独立决定 PPO）：`baselines/`。

**ns-3**：

- 执行语义见 `decisions.md` 第 8 节。
- Python 端：`backend/ns3/`。
- C++ 模块：`simulator/ns-3-external-contrib/fanet-scheduler/`。

**实验脚本**（`tools/`）与规格（`configs/experiments/*.json`）：

| 用途 | 脚本 |
| --- | --- |
| 按规格批量评估并汇总 | `e11_compare.py`（单个规格）、`run_specs.py`（多个规格共用一个队列）、`e10_ns3.py`（含 ns-3） |
| 批量训练并选检查点 | `train_runs.py`（按内存上限排队），`e13_train.py`（E13） |
| 各实验的汇总 | `e12_channel.py`、`e13_data.py`、`e14_summary.py`、`e15_summary.py` |
| 与方法无关的统计 | `e14_topology.py`（拓扑）、`e15_connectivity.py`（可用链路与可达业务） |
| 数据转换与 B 类分析 | `tools/data/`：`build_vasarhelyi.py`、`build_bonnmotion.py`、`build_verdoucq.py`、`ucsb_linkmodel.py`、`ucsb_rssi.py` |
| 报告页 | `build_report.py`、`report_data.py` |

## 5. 快速运行

需要 Python ≥ 3.11，只用 CPU。

```bash
python3.11 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest -q          # 约 1 min；未构建 ns-3 时自动跳过 ns-3 测试
.venv/bin/fanet-next components        # 列出每个职责的全部实现及其角色
.venv/bin/fanet-next train --config configs/smoke.toml --run-dir results/runs/smoke   # 约 20 s 的冒烟训练
```

- ns-3 需要先运行 `tools/ns3/setup.sh`：按 `dependencies/*.lock` 下载源码，打补丁并编译。
- 正式训练和评估耗时较长。
  - 一次学习基线训练要 1–2 GiB 内存；
  - 一个 ns-3 评估任务初始化时峰值内存约 2.5 GiB。

  只为阅读代码，不需要运行这些。

## 6. 值得重点审阅的地方

- **环境语义**（`decisions.md` 第 1、8 节）：
  - 路由变化后如何重新安置队列；
  - 等待区的规则；
  - 执行时累计干扰的判决；
  - ns-3 与轻量环境各自的简化。
- **约束实现**：`constraints.py` 中完整累计 SINR 的增量检查。它决定所有计划都可行，契约测试见 `tests/test_components.py`。
- **比较是否公平**：
  - 基线如何适配到完整 SINR（`decisions.md` 第 9 节）；
  - 学习基线的训练预算与检查点选择（`experiments.md`“E11 准备”）；
  - 真实数据上所有可训练基线都重新训练过（E13b）；
  - 反压用到了主方法没有的按目的地队列信息。
- **信道与门限**（`decisions.md` 第 10 节）：
  - 解码门限、规划门限、路由门限的层次，以及 E12 的路由更正；
  - 阴影的两种口径：dB 零均值与功率归一。它们会改变结论（E15、E15b）。
- **数据驱动评估的设定**（`decisions.md` 第 11 节）：
  - 群集 30 用 66 m 单跳距离；
  - Verdoucq 整体缩放 8.57 倍；
  - BonnMotion 只换水平运动。

  这些都按与方法无关的拓扑统计事先确定。
- **统计做法**：
  - 先按训练种子平均，再按场景配对，算 95% 置信区间；
  - 没有做多重比较校正；
  - 测试种子的使用记录见 `known-issues.md` 第 18 条。
