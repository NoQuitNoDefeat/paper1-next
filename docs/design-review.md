# 设计审视：当前方案是否限制得太死（2026-10-04，供讨论，未定）

用户的问题：在多 UAV 多跳组网中，我们想根据可观测信息训练一个在 MAC 层决定“是否发送”的通信资源管理策略。现在的方案是不是限制太死，导致评论者不能如预期那样起作用？具体是三问：

1. 真实的多跳网络里，有哪些关键取舍需要学习？哪些发送选择会明显改变后续的拥塞、交付和时延？
2. 当前代码是否允许模型做这些取舍，是否给了它所需的可观测信息？
3. 针对这些取舍，什么训练方式和结构最合适？双图、微步 PPO、摘要和约束控制器都是候选，不预设答案。

## 0. 结论先行

1. **现在的方案不决定“是否发送”，只决定“先发哪条”。**
   - 每个周期，控制器一定把可行链路选到极大，策略只能通过选择顺序影响最后的集合。研究方案第 3 节称之为“起点无学习式 STOP”。
   - E11 中除空间 TDMA 外，所有基线也被补成了极大计划。
2. **被保留下来的这个决定，单次影响很小，这是评论者只能判断局面的直接原因。**
   - 同一状态下，不同计划的长期回报只差约 0.004（D3）。
   - 评论者的局部误差约 0.036，训练中每个样本的误差为 0.08–0.1，所以它分不出动作，只能判断局面好坏（D3、E18）。
3. **动作空间外的取舍，影响有大有小**（第 2、3 节）：
   - **衰落裕量**：先前写作“冒多大风险换空间复用，影响最大”，有误（2026-10-05 更正）。引用的 0.899 / 0.832 / 0.718 是路由问题修正前的数字；修正后（E12b）为 0.908 / 0.820 / 0.479。同一个裕量同时决定路由、候选和可行性，主要通过路由的可用距离起作用，所有方法受影响相同。这不是“策略可学的冒险取舍”的证据。
   - **不往拥塞的下游发**：有影响，但量级有限。D4 中，一个简单的“不往满队列发”规则只在高负载下使 LQ 的交付率提高 0.94 个百分点，时延还升高；主方法没有“不发”的动作，中继丢包却明显少于 LQ；但减少的主要是路由更新后转队溢出的丢包，见第 10 节（2026-10-05 更正）。
   - **按目的地挑包**：主要影响时延。用目的地信息的反压，时延比主方法低 0.12–0.58 s。
4. **评论者能否评判动作，主要取决于学习信号，而不只是动作空间。**
   - 扩展动作空间不会根本改变评论者的处境。
   - 按邻域分解的局部评论者，在当前训练规模下也不起作用（D5，见第 9 节）：落点外一跳基本就是整个网络，划不出噪声更少的局部；而且一半以上的后果经由信道冲突和其他队列传到落点和下游路由以外。
5. **建议**：先在开发集上分步检验，再决定是否扩展问题定义（第 6 节）。扩展问题定义属于主方法变更，由作者决定。

## 1. 现在的方案实际在学什么

| 方面 | 现状 |
| --- | --- |
| 决策 | 每个周期 20 ms，从候选链路（队列非空、在路由上、单独发送时信噪比够）里逐条选择，直到没有可行候选，得到极大可行集合。没有 STOP。被选中的链路发送最多 9 个包 |
| 约束 | 半双工、单射频；完整累计 SINR（按决策时的信道估计，留衰落裕量） |
| 不由策略决定的 | 路由（最少跳数，每 25 个周期更新一次）、发射功率和速率（固定）、队列内发哪些包（先进先出）、丢包（队列满即丢） |
| 观测 | 链路：本队列占用、队首等待、是否在路由上、信噪比裕量、距离及其变化、链路年龄、存活度、质量趋势、反向队列。节点：出队列总量、最满出队列、等待区、位置、速度、度、邻居稳定性。冲突图：共享端点和干扰预算。候选链路的表示包含两端节点经图传播后的信息 |
| 学习信号 | 全网每周期一个奖励（服务 − 0.5 队列 − 0.5 时延压力 − 20 × 丢包率），PPO，λ = 0.95，从 LQ 模仿起步 |

E6 已经说明：没有已选摘要时，策略相当于每个周期学一个优先级顺序，再由控制器按掩码选出可行集合。

## 2. 多跳网络中的关键取舍（问题 1）

| 取舍 | 换的是什么 | 后果在何时、何处出现 | 本项目中的证据 |
| --- | --- | --- | --- |
| A. 发还是不发（流量控制） | 往拥塞的下游发，包可能在中继被丢，已用的信道白费；不发则包留在上游，可能在源端溢出，但腾出信道 | 中继丢包在**同一周期**的接纳阶段发生，就在发送端和接收端附近 | 丢包 88–99% 是缓存溢出。中继丢包占产生的包：LQ 在 load_high 为 17.7%，主方法为 7.9%。D4：简单的“不往满队列发”规则使 LQ 在 load_high 交付率 +0.94 个百分点（时延 +0.07 s），default 中为零 |
| B. 冲突链路中先服务谁 | 长队列、老包、离目的地近的包、瓶颈处的链路 | 分散在之后几十个周期 | 现在唯一学习的决定。主方法相对 LQ：困难场景交付率 +0.9–2.3 个百分点，时延 −7–15%。单次决定的影响约 0.004（D3） |
| C. 冒多大风险换空间复用 | 衰落信道下多排几条链路，吞吐更高，失败也更多 | 同一周期的执行成败，只涉及该链路和它的干扰者 | 现有证据不支持：E12b 的裕量扫描（修正后 0.908 / 0.820 / 0.479）主要反映路由的可用距离，同一裕量同时决定路由、候选和可行性，各方法受影响相同（2026-10-05 更正，原引用的是修正前的数字） |
| D. 按目的地和剩余路径挑包 | 先送快到目的地的包，或挑下游对应队列有空位的包 | 之后几个周期 | 用了目的地信息的反压，时延比主方法低 0.12–0.58 s，但丢包更多 |
| E. 赶在链路断开前发送 | 链路将断时先把队列发空 | 下一次路由更新时 | 重新排队的包数是产生包数的 0.6–1.5 倍；等待区溢出和超时只占丢包的 1–12% |
| F. 功率与速率 | 覆盖、干扰与单链路速率 | 同一周期 | 本项目未建模 |
| G. 路由与负载均衡 | 绕开拥塞的中继 | 较长时间 | 网络层，固定为最少跳数 |

明显改变后续拥塞、交付和时延的：

- C 的影响现有证据不支持（见上表更正）；
- A 在拥塞时有约 1 个百分点量级的影响；
- D 主要影响时延；
- B 每次影响小，但累积起来就是主方法相对 LQ 的全部改进。

## 3. 当前代码能否做这些取舍、能否看到所需信息（问题 2）

| 取舍 | 动作空间里有没有 | 所需信息有没有 | 说明 |
| --- | --- | --- | --- |
| A. 发还是不发 | **没有**：没有 STOP，计划一定极大 | 部分：能看到接收端的出队列总量和最满的出队列；看不到本链路的包到了接收端各进哪个队列、那些队列是否已满 | 报告里已有 `queue_dst` 和 `next_hop`，模型没有使用 |
| B. 先服务谁 | 有 | 有 | |
| C. 冒险换复用 | **没有**：控制器按固定裕量判可行；理想信道下没有失败 | 有信噪比裕量和干扰预算 | 衰落信道实验（E12b、E15b）中这个取舍存在，但由配置决定 |
| D. 按目的地挑包 | **没有**：队列先进先出，一条链路只能整体发送 | **没有**：没有目的地构成，也没有剩余跳数 | |
| E. 赶在断链前发 | 部分：只能通过先后顺序 | 部分：有存活度、质量趋势、距离变化；没有路由更新时刻 | |
| F、G | 没有 | — | 超出当前范围 |

所以，你的判断有道理：模型能学的取舍只有 B，以及 E 的一部分。A、C、D 一部分被动作空间挡住，一部分被观测挡住。

## 4. 与“评论者没有如预期起作用”的关系

- 评论者要评判动作，前提是不同动作的后果之差大于它的误差。现在能选的只有 B，单次后果只有约 0.004，所以它只能判断局面好坏（D3、E18）。
- 这一点有两个来源：
  1. **动作空间窄**：保留下来的决定影响小。C 和 A 的后果出现在同一周期，比 B 更容易学。
  2. **学习信号是全网的**：一个决定只影响几个相邻的队列，但奖励和评论者都覆盖全网，其余部分的随机性全部成了噪声。按邻域分解的局部回报，噪声会小得多。
- D4 说明：只把 A 加进动作空间，收益约 1 个百分点量级，而且主方法已经通过排序得到了一部分。所以只扩展动作空间，评论者的处境不会根本改变；局部评论者才直接提高它的分辨率。

## 5. 训练方式与结构的候选（问题 3）

| 组成部分 | 判断 | 理由与需要检验的 |
| --- | --- | --- |
| 双图编码（通信图 + 冲突图） | 保留，扩展特征 | 多跳拓扑和干扰冲突都需要图结构。补充：本链路的目的地构成、接收端对应下一跳队列的空位、剩余跳数、距下次路由更新的周期数 |
| 约束控制器 | 保留可行性检查，放开“必须选满” | 可行性由控制器保证，这是安全的设计；“不发”应由策略决定。衰落信道下，可以把固定裕量换成可学习的风险选择（C） |
| 逐条选择（微步） | 保留，加入停止 | 两种做法：每一步多一个“停止”动作；或每条链路先判断是否参与，再排序 |
| 已选摘要 | 有停止动作后重新检验 | 现在没用，是因为控制器的掩码已经表达了“选了什么”。可以停止以后，“是否再加一条”取决于已选内容，摘要可能重新有用 |
| 评论者 | 保留全网状态价值；局部分解在当前规模下不建议（D5） | 奖励可以按节点精确分解（`StandardReward.by_node`，已实现并测试）。但网络化多智能体强化学习中截断价值函数的理论（Qu、Wierman、Li 等）要求局部转移、局部策略和影响随距离衰减；本项目是集中式策略、全网耦合的可行性约束，γ = 0.99 时理论误差界几乎没有约束力，训练网络两跳之内就是全网。D5 实测：局部范围没有信噪比增益 |
| 训练算法 | PPO 保留 | 价值学习方法要求更高的估值精度，在动作差距小的问题上更难；PPO 只需相对比较 |
| 模仿起点 | 维持 LQ | D4 中经典反压（不补满）并不优于 LQ，没有更好的教师 |
| 更重的选项 | 暂不建议 | 用模拟器对候选计划做配对推演（D3 的做法），给训练提供低噪声的比较信号；代价大 |

## 6. 建议的步骤

每一步都另设配置和结果目录，开发集先行，事先登记判定规则：

1. **补观测**：只加第 5 节列出的特征，动作和训练都不变。检验“信息不足”这一限制，代价最小。
2. **局部评论者**：D5 表明在当前训练规模下没有依据，暂不做。若论文要讨论更大、更稀疏的网络，先在那样的场景族上重跑 D5。
3. **加停止**：允许策略不发。D4 预计在拥塞场景有约 1 个百分点量级的收益。
4. **风险选择（C）**：现有证据不支持（见第 2 节更正）。若以衰落信道为主要场景，应先把路由的裕量和调度的裕量分开，再判断是否值得学习。

## 9. 评论者：“全局保目标、局部保细节”是否合理（2026-10-04 补充）

用户的问题：评论者是否应当“全局负责不丢掉整体目标，局部负责保留关键细节”？外部审查（GPT）建议分清三件事：看什么信息、输出什么、用什么成绩训练。这个拆法是对的。下面按这三件事给出结论。

**依据**：

- 诊断 D5：决定的后果落在网络的哪里（见 `experiments.md` 的“D5 结果”）。
- 一次设计评审：先逐条核对事实；再由四个独立设计者各给出一种方案，每个方案由三种角度的质疑者反驳（共 18 个代理）。
- 对 D3 数据的补充分析：真实差别集中在少数局面。

**1. 看什么信息（输入）：加细节解决不了。**

- 外部审查说现有评论者已经看到局部和全局信息，核对属实。它只能看到汇总后的形式：候选的平均、节点的平均和最大。
- 但 D3 显示，评论者在各计划之间给出的差别不是太小，而是太大（真实差别的 12 倍），而且与结果无关。问题不是细节被平均掉了。
- C（让评论者看见已选链路）和 S（给评论者独立编码器）两次加强输入，都没有改变这一点。

**2. 用什么成绩训练（目标）：局部回报在当前规模下不降噪。**

- 奖励可以按节点精确拆分，不重复计数（已实现并测试）。
- 但 D5 表明，落点外一跳就覆盖了约 92% 的差别和 100% 的噪声，划不出噪声更少的局部。
- 一半以上的后果经由信道冲突和其他队列，传到落点和下游路由以外。

**3. 输出什么（分项价值、动作相对评价）：都受同一个限制。**

- 分项价值相加可以保持原目标，但不会降低噪声。
- “同一局面下这个选择比那个好多少”的相对评价，如果用同样的回报训练，仍然学不到（评审中称为对照 R0）；如果用模拟器的配对推演训练，会遇到两个问题：
  - 推演只覆盖一个未来（同一场景的业务是预先生成的）；
  - 噪声的均方根比中位数大 4–12 倍。

**真正的限制在信号本身**：

- 每个决定的真实差别平均只有约 0.004；
- 差别集中在少数临界局面：最大的 3 个状态占一半，前 10 个占 75%；
- 在策略自己的候选中每次都挑最好的，每个决定只多 +0.00125。这个估计不稳健：换一种分半方式为 +0.0007 [−0.0011, +0.0025]。而且 D3、D5 的状态都取自回合前段（第 60–150 个周期），拥塞局面下的提升空间没有测过。

**结论**：

- 作为一般原则，“全局保目标、局部保细节”是合理的。
- 其中“用局部回报训练”在已测的三个场景族中都没有依据（D5、D5b）。
- “仍用全网回报，但让评论者看清每条链路、下游队列和已选计划”只被 C、S 部分触及，尚未检验，不能排除。
- 更有希望的方向不是改评论者的结构，而是：
  - 让决定本身更有影响（第 6 节的“加停止”“风险选择”）；
  - 或者把学习集中到少数临界局面。

**低成本检验的结果**（2026-10-05，作者决定先做；详见 `experiments.md` 的“E19 结果”和“D5b 结果”）：

- E19：每次迭代 4 倍数据、梯度步数不变，交付率不变，三个场景族的时延显著升高 0.05–0.15 s，按奖励 A 计的评估分数显著降低 1.2–4.3%。伴随现象是每次更新的策略变化减半、策略离模仿起点更近，以及奖励尺度前期的变化过程不同。原因尚未确定，由 E20 检验。
- D5b：稀疏 24 节点和真实群集 30 架上，局部范围的信噪比增益分别为 0.63 和 1.17（置信区间 0.82–2.10），都不满足局部性条件。这只否定了“用局部回报训练”；“全网回报 + 看清局部细节”的评论者尚未检验。

原先列出的两项检验：

1. **加大每次迭代的数据量**：定稿方法用 4 倍的环境数训练，3 个种子，开发集。若有改进，说明瓶颈在学习信号的噪声；若没有，说明瓶颈在别处。
2. **在更大、更稀疏的场景族上重跑 D5**，例如 24 节点或真实群集 30 架，看那里是否出现局部性。

## 10. 结构排查：除评论者外，哪些地方限制了优化目标（2026-10-05）

**用户的问题**：现在优化得不好，除了评论者，别的地方甚至整体结构可能也有问题。有哪些潜在的结构和修改能达成优化目的？

**做法**：

- 一次结构排查，共 22 个代理：问题定义与动作空间、观测、策略结构、训练算法、奖励与目标、评论者、训练数据与评估，每层一个分析者、两个质疑者（查证据、查代价），最后综合排序。
- 评审代理在临时目录里跑了一些只读的探针。凡是下文标明“已复核”的，都用提交的工具重新跑过；标明“探针”的，只是方向性证据：多为单种子，场景与开发集重叠，个别参数是在同一批场景上调的。

### 10.1 诊断

**已复核**：

1. **主方法在拥塞场景的优势主要来自避开路由更新后的转队溢出**（`experiments.md` 的“D4 补充：丢包来源”，已知问题第 26 条）。这一优势依赖“每个下一跳单独限长队列 + 每 25 个周期全局重算路由”的环境设定，稳健性尚未检验。
2. **几处先前的说法有误**，已在文中更正：
   - 引用的衰落裕量数字是路由修正前的；修正后裕量主要通过路由的可用距离起作用，不是策略可学的冒险取舍；
   - 中继丢包占比应按丢包数加权（主方法 29–41%，LQ 60–72%）；
   - “每次挑最好 +0.00125”不稳健；D3、D5 只取了回合前段的状态，拥塞局面下的提升空间没有测过。

**有探针支持、尚未复核**：

3. **决定看不到包要去哪里。** 模型不读每个队列的目的地构成（`queue_dst`），服务也是先进先出，不看目的地和接收端的空位。探针中，对冻结的主方法加简单规则、不重新训练：
   - 按剩余跳数从少到多发包，load_high 交付率 +1.4 个百分点、时延 −0.10 s；
   - 给“最后一跳”的链路加分，load_high +1.5 个百分点、时延 −0.21 s（3 个种子）；
   - 规则对 LQ 同样有效，而主方法加规则后仍比 LQ 加规则好：学到的排序与规则是叠加关系，不是替代关系。
4. **不能不往满队列里发。** 探针中，主方法加“接收端放不下就不发”的屏蔽，load_high 和 nodes24 +1.3 个百分点，时延 +0.11–0.14 s；按包检查接收端空位的服务方式，+2.1 个百分点。只在拥塞时有用。
5. **一个带目的地信息、并且“放不下就不发”的启发式，在开发集 load_high 上可能比主方法高 2.4 个百分点。** 这会动摇“优于全部基线”，必须在新的场景上、事先固定参数重测。
6. **训练目标和选检查点没有表达“交付率优先”：**
   - 奖励 A 中丢包项的分母（风险包数）随策略变化，所以按奖励 A 比较不同策略可能误导；
   - 同一周期内，奖励分不出包是到达了目的地还是只走了一跳（服务后的快照在接纳之前），所以对“最后一跳优先”的梯度很弱；
   - “交付率优先”只靠选检查点实现，而选检查点只用 16 个回合、只看默认场景，容差 0.2 个百分点，比配对置信区间（±0.24–1.0）还窄。
7. **训练数据的相位问题。** 8 个训练环境同时开始、同时结束，约 36% 的迭代里没有回合后段（第 300 个周期以后）的数据，而后段集中了约 87% 的丢包。这不等于训练看不到后段（回合跨迭代继续）；疑点是多个环境同时拥塞、同时清空，使训练批次忽忙忽闲，尚未证明是主要瓶颈（2026-10-05 更正）。

**评审认为不是瓶颈的**：编码器容量、评论者结构、PPO 的更新预算（E20 进行中，待定）、奖励尺度的前期变化（E20 U4 待定）。

### 10.2 候选修改（按预期收益与成本排序；带“★”的属于主方法变更，需作者决定）

| 序 | 修改 | 机制 | 先做的检验 |
| --- | --- | --- | --- |
| 1 ★ | 按目的地的发包顺序：同一条链路上，剩余跳数少的包先发 | 先让快到目的地的包离网，腾出缓存；同样的吞吐下时延更低 | 新场景（偏移 ≥ 48）上的组合评估，不训练 |
| 2 ★ | 接收端放不下就不发（确定性规则，不学习） | 不再把包送进必丢的队列 | 与 1 同一组合评估 |
| 3 | 目标与选检查点对齐：丢包权重扫描（40、80）、奖励 B、学习率退火、按配对交付率比较各臂 | 让训练和选择真正以交付率优先 | E20 之后，先跑漂移明显的种子 |
| 4 ★ | 观测加入目的地构成、接收端对应队列的空位、剩余跳数；用带目的地信息的启发式做模仿教师；必要时让奖励在同一周期内看到交付 | 让策略自己学会 1、2 的取舍 | 3 个种子 + 只模仿对照，新开发场景 |
| 5 ★ | 训练数据加重拥塞场景 | 价值集中在拥塞局面 | 只在拥塞局面诊断（D3c）显示有提升空间时做 |
| 6 | 训练环境错开回合相位；奖励尺度的初始计数随环境数调整 | 消除训练数据的相位偏差 | 与下一组新对照一起做 |

**不建议**：学习式停止（在奖励 A 下“不发”几乎没有梯度）、全网回报加丰富输入的评论者作为独立工作（可在 4 中顺带）、Transformer 或指针网络解码、精确最大权、改变 γ。

### 10.3 分阶段计划

**第 0 阶段（只评估，不训练，与 E20 错开内存）**：

1. 指标：考虑丢包的时延（按产生的包计准时率）、按跳数分组的交付率和时延、丢包按原因分。
2. 新开发场景（偏移 ≥ 48，32 个场景，三个场景族）上的组合评估：
   - 发包顺序：先进先出 / 剩余跳数少者先；
   - 接纳：极大计划 / 放不下就不发 / 按包检查空位；
   - 策略：LQ、反压、主方法种子 0–2、带目的地信息的 LQ（参数事先固定）。
3. 路由语义的稳健性：路由更新间隔 10 和 50、错开更新时刻、低速；比较主方法与 LQ 的差距。
4. 已有检查点按采样模式和贪心模式分别评估。
5. D3c：在回合后段的拥塞局面重做 D3（E20 之后）。

**之后需要作者决定**：

- 目标的含义：“交付率不劣于 LQ，再最小化时延”（现在选检查点的做法），还是“先最大化交付率，再降时延”。这决定第 2 项的取舍。
- 发包顺序、接收端空位这类 MAC 服务规则，算不算允许的问题定义修改。
- 论文是否需要补带目的地信息的启发式基线。

**会改变方向的结果**：

- 第 3 项中，路由更新改变后主方法相对 LQ 的优势减半：先修正环境的路由语义，再谈方法改进，并相应调整论文的结论表述。
- 带目的地信息的 LQ 加“不发”在每个场景族都不差于主方法加“不发”：学到的排序的价值存疑，第 4 项成为主线，论文也需要这条基线。

### 10.4 关于“评论者是否需要重新设计”

- 现在的评论者是状态价值：判断“从当前局面出发，按当前策略，通常能拿多少”。这项工作它做得好（不同状态之间与实际回报相关 0.92–0.96），而且不可或缺（E18）。
- 它分辨不了同一局面下各计划的高低（D3）。“用局部回报训练”的改法没有依据（D5、D5b）；“全网回报 + 看清局部细节”的输入改法只被 C、S 部分触及，尚未检验。
- 结构排查的结论是：眼下限制优化目标的，主要是问题定义（看不到目的地、不能不往满队列发）、目标与选择的对齐，以及影响结果大小的环境设定，而不是评论者。目的地构成、接收端空位这些信息，加进观测时可以同时给行动者和评论者用（第 4 项），不必单独重做评论者。

## 11. 长期目标与探索路线（2026-10-05）

**长期目标**（用户确认）：根据可观测的网络、队列和信道信息，训练一个 MAC 层的通信资源管理策略。它每个周期决定哪些链路发送、哪些等待，使包**先尽可能多地送达（最大化交付率）**，再尽可能快（降低时延）。

### 11.1 现状与目标的差距

| 目标要素 | 现状 | 差距 |
| --- | --- | --- |
| 决定“发送还是等待” | 只决定顺序，计划一定极大 | 缺“等待”这个动作 |
| 先最大化交付率 | 奖励 A 是加权和，丢包权重随风险包数变化；选检查点按“不劣于 LQ 再取时延最低” | 训练和选择都没有以“交付率最大”为先 |
| 依据可观测信息判断多跳后果 | 看不到每条链路上包的目的地构成、接收端对应队列的空位、剩余跳数 | 缺信息 |
| 在合理的系统设定下成立 | 相对 LQ 的差别可能依赖“每个下一跳单独限长队列 + 定时全局重算路由” | 稳健性未验证 |
| 学习方法本身 | 评论者能判断局面、分辨不了计划（回合前段）；训练方案的配套问题未定（E19、E20） | 拥塞局面未测，训练方案待定 |

### 11.2 三步路线

**第一步：查清在哪里损失性能（第 0 阶段，只评估，不训练）。**

| 检查 | 回答的问题 |
| --- | --- |
| 丢包按“发生环节 × 位置（源节点 / 中继）”分，再看各位置的排队量 | 损失主要来自无线调度，还是来自特定的排队与改路规则？ |
| 同一套规则给所有策略：发包顺序（先进先出 / 剩余跳数少者先）× 接纳（必须发满 / 放不下就不发 / 按包检查空位） | 哪些规则本身有价值？原策略能否适应？是否缺少某种信息或动作？ |
| 带目的地信息的简单规则（参数事先固定），在新场景上与主方法比较 | 模型是否缺少判断多跳后果的信息？简单规则是否已经足够，应作为强基线或系统的一部分？ |
| 节点总缓存容量相同时，“按下一跳分别限额”与“共享容量”；路由更新间隔 10 / 50、错开更新 | 学到的能力是否只适用于当前这套环境设定？ |
| 拥塞局面（回合后段、高负载）下重做 D3 | 拥塞时决定的差别是否更大，评论者能否分辨？ |

**出口**：一份“能力需求清单”。每项发现对应一种能力：缺什么信息、缺什么动作、目标哪里没对齐、结构哪里要改。如果简单规则已经便宜、稳定地解决了某个问题，就把它作为强基线或系统的一部分，不强求神经网络包办。

**第二步：把发现转成方法（2–3 套完整方案，由第 0 阶段的结果决定取舍）。** 初步设想：

| 方案 | 看什么 | 能做什么 | 学什么 | 结构 |
| --- | --- | --- | --- | --- |
| M1：看得见目的地、会等待的学习调度器 | 加入目的地构成、接收端对应队列空位、剩余跳数 | 排序 + 每条链路可暂缓；MAC 按目的地发包 | 以交付率最大为先（例如约束形式：在交付率约束下降时延，或分阶段的奖励） | 双图编码 + 逐条选择（加停止或暂缓门）；评论者保持全网目标、输入加入局部细节，用拥塞局面的 D3 检验 |
| M2：规则底座 + 学习残差 | 同 M1 | 由确定性规则负责“放不下不发”“近目的地先发”，策略只学规则之上的排序与少量暂缓 | 同 M1 | 现有结构，规则作为环境的一部分；成本低，也是 M1 的强基线 |
| M3：学习权重 + 求解器 | 同 M1 | 网络为每条链路（或每个目的地）输出权重，负权重即等待，由贪心或精确求解器组成计划 | 同 M1 | 类似反压的结构，权重由学习得到 |

取舍原则：

- 规则就能拿到大部分收益，以 M2 为主；
- 信息有价值但规则不稳，以 M1 为主；
- 需要按目的地细分的权重，考虑 M3。
- 检查点选择改为“交付率最大优先，再取时延低”，用更多回合和多个场景族。

**第三步：验证能力，而不只是分数。**

- 给了下游信息，无效转发是否真的减少；允许等待，交付率是否提高，又没有造成长期不服务；
- 新方法是否胜过拥有相同信息和动作权限的简单规则，以及相关学习方法；
- 换场景、换合理的环境设定后，优势是否还在；
- 最后在新的测试种子、ns-3 和真实数据上确认。

**E19、E20 的位置**：辅助工作，检查现有方法怎样训练得更充分，不能代替“信息、动作、目标和结构是否选对”这一主线。


## 12. 第 0 阶段的出口：能力需求清单与方案（2026-10-06）

**更新（2026-10-06）**：

- 作者已决定：送达须满足截止时间（主设定 1 s，第二类业务 5 s），R5 作为共享底座；但 R5、双图、微步 PPO、现有评论者都是可比较的选择，不提前锁死。
- 外部审查指出本节有几处说得过满，已在原文收窄。12.3 的目标写法与“先最大化交付率”冲突，12.4 第 4 项的“上界”说法不成立；方案以第 13 节为准。

### 12.1 结论

1. **主方法相对 LQ 的交付率优势是真实的**（D7）。load_high 中它不依赖路由更新方式；nodes24 中，去掉转队丢包后优势缩小约 48%，明显受这一规则影响（2026-10-06 外部审查后收窄）。
2. **现有模型没有超过一条更强的简单规则。** 规则更好，不证明模型原来靠同一机制取得进步；补上同样的信息、按目标重新训练后能否超过，尚未检验（2026-10-06 外部审查后收窄）。只给 LQ 加上“发往目的地的包加分”（`lq_lasthop`）：
   - default 中两者持平；
   - load_high 中启发式高 1.1 个百分点，三个种子都显著；
   - nodes24 中两者持平（D6 判读 3）。
3. **与策略无关的发包和接纳规则（R5），使每个策略在拥塞场景再提高约 3 个百分点**（D6 判读 1）。R5 包括：
   - 剩余跳数少者先发；
   - 放不下就不发；
   - 服务时检查空位。

   在 load_high 中，启发式 + R5 比 LQ 高 6.7 个百分点，是主方法优势的 2.5 倍。
4. **训练目标没有对齐“先最大化交付率”。** 训练后段持续以交付率换时延（D8）。试过的几组加大更新的设置都没有带来整体改善（E20），这不证明任何训练安排都无益（2026-10-06 外部审查后收窄）。
5. **没有充分理由把改评论者放在第一位**（D3c）：训练分布内，回合后段的计划差别不更大。但 load_high 后段的差别明显更大，评论者也开始有一点分辨力，不能把 default 的判断推广到重度拥塞（2026-10-06 外部审查后收窄）。
6. **“交付率”的定义本身需要先确定**：没有截止时间时，能多存包就几乎不丢（E4）。

### 12.2 能力需求清单

| 能力 | 证据 | 定稿方法的现状 | 怎样补 |
| --- | --- | --- | --- |
| 看得见目的地：每条链路上有多少包发往接收端、剩余几跳 | 目的地信息单独带来 +0.5 / +3.7 / +2.0 个百分点；1 跳流 +10 | 观测中没有，只能间接学到一部分 | 加入观测；或直接用作规则或权重 |
| 合理的发包与接纳规则 | R5 对所有策略约 +3（拥塞），方向一致，无跳数组受损；R1 还降低时延 | 先进先出，不检查接收端空位 | 作为确定性的 MAC 底座，不必学 |
| 目标对齐“交付率优先” | D8：两个种子在训练中交付率下降、时延下降 | 奖励 A 是加权和；选择是“不劣于 LQ 后取时延最低” | 约束或分阶段的目标；交付率优先的选择 |

| 评论者的分辨力 | default 中不需要；重度拥塞时差别变大 | 状态价值，分辨不了计划 | 暂不改；新方法若在重度拥塞下训练，重测 D3 |
| 更多更新 | E20：都更差或持平 | — | 不改 |

### 12.3 方案

按预登记映射，以 M2 为主，M3 列为备选。M1 没有触发，改作 M2 的消融。

所有方案都必须胜过拥有同等信息和规则的简单基线，标准是 ≥ 0.5 个百分点。这条基线目前是“启发式 + R5”：

- default 98.80%；
- load_high 79.59%；
- nodes24 91.75%。

| | M2：规则底座 + 学习（主推） | M3：学习权重 + 求解器（备选） |
| --- | --- | --- |
| 规则 | R5，所有方法相同 | R5，所有方法相同 |
| 观测 | 现有特征，加上每条链路的目的地构成（发往接收端的包数、按剩余跳数分档的包数）和接收端对应队列的空位 | 同左 |
| 动作与结构 | 保留双图微步，逐条选择 | 网络为每条链路输出一个权重，由贪心最大权调度器组成计划；权重 ≤ 0 即不发。一次产生一个计划，没有微步的功劳分配问题 |
| 起点 | 模仿“启发式 + R5”，代替模仿 LQ | 回归启发式的权重 |
| 目标 | 交付率优先（已更正：原写“丢包率不高于起点、再降时延”，与“先最大化交付率”冲突，见第 13 节） | 同左 |
| 选择 | 交付率优先，平手取时延低 | 同左 |
| 依据 | 恢复比例 2.5 | 反压在 R4 / R5 下比 LQ 高 2.6–3.7（只在 load_high） |
| 风险 | 启发式 + R5 已经很强，学习的增量可能很小 | 可能只学成一个更好的启发式权重 |
| 成本 | 中：扩展观测、换模仿教师、改目标 | 中：新动作头和求解器接口，可复用现有调度器 |

**M1 改作消融**：去掉规则底座，看网络能否自己学会这些规则。证据表明这些规则对所有策略都有效、写成规则很便宜，让网络去学没有必要。

### 12.4 需要作者决定的

1. **交付的定义（研究问题的设定）。** 这一项决定了“先最大化交付率”是否有意义，也影响后两项。
   - a. 维持现状：不设截止时间，排空 20 s。此时单纯最大化交付率会鼓励囤积。
   - b. 给包设截止时间，超时丢弃，交付率按截止前送达计。环境已有 `deadline_s` 选项。截止时间的取值应来自目标业务，例如控制或遥测的时限。
   - c. 不设截止时间，但把“2 s 内送达率”作为主指标。这个指标已有。

   我的建议是 b。它符合实际业务，也让“等待”有了真实代价，学习可能更有用武之地：哪些包还来得及，需要预判。
2. **R5 的归属。** 建议作为所有方法共享的 MAC 底座，而不是本方法独有的部分。这样比较公平，论文的主张变为“在合理的 MAC 规则下，学习调度相对强规则基线的增益”。
3. **缓存组织。** 两种选择：
   - 维持“每个下一跳单独限长”：与此前所有实验一致；
   - 改为节点共享：E4 显示影响极大。

   应依据目标系统选择。建议主设定不变，共享缓存作为敏感性分析。若选 1b，囤积的优势会受到截止时间的限制。
4. **下一步的顺序。** 建议：
   1. 按决定 1 确定定义，重跑各基线（只评估，成本低）。
   2. 寻找改进机会：用模拟器对“启发式 + R5”做一步推演改进（每个周期比较几份候选计划的推演结果）。该策略不可部署。它找到的改进是可达改进的下界；找不到，不说明不存在（只试少数候选、只看有限时间都可能漏掉）（2026-10-06 外部审查后收窄）。
      - 推演改进明显时，说明至少有一类可学的改进，推演本身也可以作为训练信号（第 13 节）；
      - 不明显时，只说明这种推演找不到，不作“没有学习空间”的结论。
   3. 预登记后，在开发集上并行做 M2 和 M3，再选一个进入确认。
